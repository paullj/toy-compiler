# T0032: `?` needs an Option/Result operand and return

The postfix `?` operator desugars to a match + early-return over an `Option[T]` or
`Result[T, E]`. On the happy variant (`some`/`ok`) it unwraps the payload and control
continues; on the residual variant (`none`/`err`) it early-returns that residual from
the ENCLOSING function.

For that to type-check, two things must both be `Option`/`Result`:

- the operand `?` is applied to, and
- the enclosing function's return type (it has to be able to absorb the residual).

Using `?` on a value that is not an `Option`/`Result`, or inside a function whose
return type cannot hold the residual, is this error:

```
fn first(n: int) -> Option[int] {
    v := n?          // error: '?' operand must be an Option or Result, got int
    return Option.some(v)
}

fn get(o: Option[int]) -> int {
    v := o?          // error: '?' requires the enclosing function to return an Option or Result, but it returns int
    return v
}
```

Fixes:

- Apply `?` only to an `Option`/`Result` value (call the fallible function that
  returns one, or wrap the value with `Option.some(..)` / `Result.ok(..)`).
- Make the enclosing function return the matching `Option`/`Result` so the `none`/`err`
  residual has somewhere to go, then unwrap the final value at the call site with a
  `match`.

The operand's family must also MATCH the enclosing return's family (an `Option?` in a
`-> Result` function, or a `Result` error-type mismatch, is the separate T0033).
`From`-style error widening is not yet supported; until then a
`Result` `?` requires the SAME error type end to end.
