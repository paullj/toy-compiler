# T0028: missing arithmetic impl

The `+`, `-`, `*`, and `/` operators desugar to the prelude arithmetic protocols
`Add`, `Sub`, `Mul`, and `Div`, each homogeneous (`Rhs = Self`, `Out = Self`):

```
protocol Add { fn add(self, other: Self) -> Self }
protocol Sub { fn sub(self, other: Self) -> Self }
protocol Mul { fn mul(self, other: Self) -> Self }
protocol Div { fn div(self, other: Self) -> Self }
```

The builtin numeric scalar `int` ships compiler impls for all four, so `int`
arithmetic always works and lowers to a single inline machine op (no call). Unlike
`Eq`/`Ord`, `str` and `bool` do NOT get arithmetic impls: `str + str` concatenation
would allocate on the heap, which is deferred to the heap/stdlib roadmap, so
`str + str` (and `bool + bool`) is an error here rather than a silent allocation.

A user value type (a struct or enum) must provide its own impl; using an arithmetic
operator on one that has none is an error at the operator.

```
struct V2 { x: int, y: int }

fn main() -> int {
    a := V2{ x: 1, y: 2 }
    b := V2{ x: 3, y: 4 }
    return (a + b).x   // error: '+' requires an 'Add' impl for type 'V2'
}
```

Give the type the matching impl:

```
impl V2 has Add {
    fn add(self, o: V2) -> V2 { V2{ x: self.x + o.x, y: self.y + o.y } }
}
```

Both operands must have the SAME type — arithmetic is homogeneous (`Rhs = Self`), so a
mixed-type expression (`int + str`) is a separate "same type" error. The result type is
`Self` (`Out = Self`), enforced by the conformance-signature check. `Add` has no
structural default, so it is never auto-derived — the impl is always written by hand.
