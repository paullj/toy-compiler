# R0013: core import private

The bundled `core/` modules are the standard library's private layer. Their
functions skip the checks the `std/` wrappers make, so a user program that calls one
directly can read or write past the end of a buffer. Only a bundled module (`core/`
or `std/`) may import a `core/` module; a user module imports the `std/` module that
wraps it.

```
import core/mem            // error: module 'core/mem' is private to the standard
                           // library; import std/vec, std/map or std/set instead
fn main() -> int {
    a := mem.ga_new[int]()
    mem.ga_push[int](a, 7)
    return mem.ga_get[int](a, 100000)
}
```

| core module | use instead |
|---|---|
| `core/mem` | `std/vec`, `std/map`, `std/set` |
| `core/text` | `std/str` |
| `core/sys` | `std/io` |
| `core/ffi` | `std/math` |
| `core/os` | `std/os`, `std/time` |
| `core/fs` | `std/fs` |
| `core/*_selftest` | `std/gc` |

Fixes:

- Import the `std/` module the error names and use its safe API (`xs[i]`,
  `xs.push(v)`, `io.println(s)`, `gc.collect()`).
- If you are extending the standard library, put the code in a bundled `std/`
  module, which may import `core/`.

A bundled module counts as bundled only when a program imports it. Checking a
`packages/lib/std/*.toy` source file on its own, or opening it in an editor, makes it
the program's entry, a user module, so its `core/` imports report R0013 (with a hint
that may name that same module). A dev build checks it with `--dev-core-imports`.
