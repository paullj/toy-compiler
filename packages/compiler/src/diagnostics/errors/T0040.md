# T0040: argument type mismatch

An argument's type is not assignable to the parameter it is passed for. The
diagnostic names the position, the expected and actual types, and the callee's
full parameter-type signature, with a secondary label at the definition.

```
fn takes_int(a: int) -> int { return a }

takes_int("hi")   // error: argument 1: expected int, got str; 'takes_int' takes (int)
```

In a pipe, the piped value is argument 1:

```
"hi" |> takes_int   // error: argument 1 (the piped value): expected int, got str; ...
```

Fixes:

- Pass a value whose type matches the parameter.
- Follow the "defined here" label to the definition to see the parameters.
