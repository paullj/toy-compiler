# W0012: function value is never called

An expression statement is a function value that nothing calls: a function name, a
bound method, a field, local or element of function type, a lambda, or a `_` capture.
The statement makes the value and throws it away, so it does nothing.

```
struct Counter { n: int }

impl Counter {
    fn bump(mut self) { self.n = self.n + 1 }
}

fn main() -> int {
    c := Counter { n: 0 }
    c.bump        # W0012: function value is never called; did you mean 'c.bump()'?
    return c.n    # 0
}
```

A function name and `recv.m` are values, so `c.bump` is no longer an error: it is the
bound method, a closure over `c`, and the statement drops it before it runs. The same
holds for `one` where `one()` was meant, `xs.sort` for `xs.sort()`, and `h.run` for a
field `run` of function type. The message spells the call from the source: `()` when
the function takes no arguments, `(..)` when it takes some.

- A lambda as a statement (`fn() { .. }`) never runs its body. Write the statements
  without the lambda, or bind it with `:=` and call it.
- A `_` capture as a statement (`show(_)`) makes a function of one parameter, so `show`
  never runs. Before captures, that statement passed a local named `_`; rename the local
  to keep that meaning, or call the capture.

A function value that is used does not warn: one that is bound (`f := c.bump`),
assigned, passed, returned, piped, or is the value of a block or function that is
used. A call that returns a function (`make_adder(1)` as a statement) does not warn
either: the call runs, and its result is dropped like any other value.

Add the parentheses to call it, or remove the statement. This is a warning, so it does
not fail the build; `--deny-warnings` promotes it (and every warning) to an error, and
`--allow W0012` silences it.
