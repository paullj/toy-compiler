# W0013: method has the name of a field of function type

A method has the same name as a field of function type on its receiver struct, so one
name means two functions, and which one a use reaches depends on how it is written:

```
struct H { run: fn(int) -> int }

impl H {
    fn run(self, x: int) -> int { x + 1000 }   # W0013
}

fn main() -> int {
    h := H { run: fn(x) { x + 1 } }
    a := h.run(1)    # 1001: a call selects the method first
    f := h.run       # the field: a value reads the field first
    return a + f(1)  # 1001 + 2
}
```

Both rules are deliberate. `recv.m(..)` selects a method named `m` first and only then a
field of function type named `m`, so a method call keeps working when a field of that
name is added. `recv.m` without a call is the field when there is one, and the bound
method only when there is none, so reading a field never turns into a closure. Each rule
is simple alone; together they make `h.run(1)` and `f := h.run; f(1)` call different
functions, which the code does not show.

The warning sits on the method's name, and points at the field when it is declared in
the same module. It fires for an inherent method, a conformance method (`impl H has P`)
and a method of a generic struct (`impl H[T]`) alike. A field of any other type cannot
be called, so it is never taken for the method and does not warn; nor does an
associated function (no `self`), since `h.run(1)` on one is already the error T0018.

Rename the method or the field. If the overlap is intended, `--allow W0013` silences it.
This is a warning, so it does not fail the build; `--deny-warnings` promotes it (and
every warning) to an error.
