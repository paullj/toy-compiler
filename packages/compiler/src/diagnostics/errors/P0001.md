# P0001: expected token

The parser reached a point where a specific punctuation mark or keyword was
required (for example a `)`, `{`, `:`, or `=`) but found something else.

Check for a missing or misplaced delimiter near the reported location.

Items of a list (arguments, parameters, list elements, type arguments) are separated
by `,`. A missing one is reported at the item after it:

```
add(1 2)    // error: expected ',' or ')' after an argument
add(1, 2)
```

A block that runs into the end of the file is missing its `}`. Inside a block,
`fn name(..)` declares a local function, so when a function's closing `}` is
missing, every top-level function after it parses as nested in it and the block only
ends at the end of the file. The error is then reported at the `fn` it suspects: the
first nested one written no further right than the function it was parsed in, as a
sibling declaration is. A secondary label marks that enclosing function.

```
fn main() -> int {
    if true {
        return 1
    return 0
}                  // closes the `if`, not `main`

fn other() -> int { 2 }   // error: expected '}' before this 'fn': it was parsed as a
                          // function nested in the block above, which runs to the end of the file
```

Add the missing `}` before that `fn`. An indented nested function is a real local
function, so when every nested one is indented no function is blamed, and the error
is the plain "expected '}' to close block" at the end of the file.

A method takes `self` and a local function never does, so inside an `impl`
the next method ends a method body that lost its `}`, and the error is reported
at that method:

```
impl C {
    fn a(self) -> int {
        if true { 1 } else { 2 }
                   // a's `}` is missing
    fn b(self) -> int { 2 }   // error: expected '}' to close block
}
```
