# P0014: invalid pipe target

`x |> f(a)` passes `x` as the first argument of `f`, so it means `f(x, a)`. The part
after `|>` must be a function name or a call, and it must be the end of the pipe.

    x |> f                 // right: f(x)
    x |> math.max(3)       // right: math.max(x, 3)
    x |> parse?            // right: parse(x)?
    x |> 5                 // error: 5 is not a function
    x |> f().len()         // error: .len() extends the pipe target
    x |> f == y            // error: == follows the pipe target

To use the result of a pipe, put the pipe in parentheses:

    (x |> f).len()
    (x |> f) == y

The error also occurs when a pipe has no value on its left. A line that starts with
`|>` continues the line before it, so that line must end with a value:

    return                 // error: `return` has no value to pipe
        |> f(x)

    if ok { .. }           // error: an `if` statement is not a value
        |> f
