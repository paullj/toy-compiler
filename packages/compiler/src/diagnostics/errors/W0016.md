# W0016: method has the name of a variant

An enum has a variant and a method that takes `self` with the same name, so one name
means two things, and which one a use reaches depends on how it is written:

```
enum E { A(int), B }

impl E {
    fn B(self) -> int { 7 }   # W0016
}

fn main() -> int {
    e := E.B       # the variant B
    return e.B()   # 7: the method
}
```

Through the type, `E.B` is the variant; on a value, `e.B()` calls the method. Both stay
reachable, so this is a softer warning than W0015, where an associated function of a
variant's name can never be called. Still, a reader who sees `e.B()` and `E.B` side by
side cannot tell they are unrelated.

The warning sits on the method's name, and points at the variant when the enum is
declared in the same module. It fires for an inherent method, a conformance method
(`impl E has P`) and a method of a generic enum (`impl O[T]`) alike. A struct has no
variants, so its methods never warn, nor does a method whose name no variant has.

Rename the method or the variant. If the overlap is intended, `--allow W0016` silences
it. This is a warning, so it does not fail the build; `--deny-warnings` promotes it (and
every warning) to an error.
