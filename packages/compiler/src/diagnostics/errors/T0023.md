# T0023: unsatisfied bound

A generic function is called with a type argument that does NOT conform to the
protocol its type parameter is bounded by. A bound `[T has P]` means "any `T`, so long
as `T has P`" — the body may only call `P`'s methods on a `T`, and every instantiation
must supply a type that has an `impl <type> has P`. This is a USE-SITE error: it names
the offending type and the protocol, and points at the call that requested the
instantiation. That instantiation is skipped (no cascade of per-instance errors).

```
protocol Doubler { fn dbl(self) -> int }
struct P { x: int }
impl P has Doubler { fn dbl(self) -> int { self.x * 2 } }

struct Q { x: int }         // Q has NO `impl Q has Doubler`

fn twice[T has Doubler](v: T) -> int { v.dbl() + v.dbl() }

fn main() -> int {
    return twice(Q{ x: 1 }) // error: type 'Q' does not conform to protocol 'Doubler'
}
```

Add the missing conformance (`impl Q has Doubler { fn dbl(self) -> int { .. } }`), or
call the generic function with a type that already conforms.

A generic impl conforms every instance of its type, as far as its own bounds allow:
`impl Box[T has Show] has Show` makes `Box[P]` conform to `Show` only where `P` does. When
such an impl covers the type but a bound fails, the message names the type argument that
fails it:

```
error[T0023]: type 'Box' does not conform to protocol 'Show'; its generic impl needs type argument 'Q' to conform to 'Show'
```

Give that type argument the conformance, or call with an instance whose type arguments
have it.
