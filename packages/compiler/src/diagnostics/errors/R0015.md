# R0015: static library

toy links only dynamic libraries. An `extern "name"` block or a `-l` flag named a
static archive (`.a`) or an object file (`.o`), or the library search found only
`lib<name>.a` and no `lib<name>.dylib`. The emitted binary loads each library with
dyld at run time, so there must be a `.dylib` to load; copying archive code into the
binary (static linking) is not supported yet.

```
extern "libsqlite3.a" {   // error: library 'libsqlite3.a' is a static library;
    fn sqlite3_libversion_number() -> int32   // toy links only dynamic libraries (.dylib)
}
```

```
// toy build main.toy -L vendor   (vendor/ holds only libfoo.a)
extern "foo" { fn foo_init() }    // error: library 'foo' is only a static library
                                  // ('vendor/libfoo.a'); toy links only dynamic libraries
```

Fixes:

- Build or install the library as a dynamic library (`cc -shared -o libfoo.dylib ...`)
  and name it, or the folder it is in with `-L`.
- Name the library without an extension (`extern "foo"`, `-l foo`) so the search looks
  for `libfoo.dylib`.
