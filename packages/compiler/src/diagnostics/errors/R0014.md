# R0014: ambiguous module

An `import` names a module that more than one file could be. A non-`std`/`core` import
path `a/b` is looked up as `a/b.toy` and as the folder module `a/b/mod.toy`, in the
module root (`--root`, default the entry file's folder) and in every extra root (`-I`);
exactly one of those files must exist. The error lists every file the path matched, so
none silently shadows another.

```
// toy build src/main.toy -I lib
// with both src/extra.toy and lib/extra.toy on disk:
import extra   // error: imported module 'extra' matches more than one file ('src/extra.toy', 'lib/extra.toy')

// with both util.toy and util/mod.toy on disk:
import util    // error: imported module 'util' matches more than one file ('util.toy', 'util/mod.toy')
```

The same file reached through two roots (an `-I` that repeats the module root) is one
module, not this error. Two import paths that reach one file are: each file is imported
by one path. With `-I util`, `import util/math` and `import math` name the same file:

```
// toy build main.toy -I util
import util/math
import math   // error: imported module 'math' is the file 'util/math.toy', which is already imported as 'util/math'
```

Fixes:

- Rename or remove one of the files (keep either `util.toy` or `util/mod.toy`).
- Or drop the `-I` root that should not supply this module.
- Or import the file by the same path everywhere.
