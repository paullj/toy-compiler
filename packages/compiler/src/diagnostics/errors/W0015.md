# W0015: associated function has the name of a variant

An enum has a variant and an associated function (one without `self`) of the same name.
`E.A(..)` always builds the variant, so the function can never be called:

```
enum E { A(int), B }

impl E {
    fn A(n: int) -> E { E.B }   # W0015
}

fn main() -> int {
    e := E.A(1)   # the variant A(1): fn A never runs
    return match e {
        E.A(v) -> v,
        E.B -> 99,
    }
}
```

A variant keeps its name so that adding an associated function never changes what an
existing `E.A(..)` builds. The function is then unreachable: through the type the name
is the variant, and an associated function is never called on a value.

The warning sits on the function's name, and points at the variant when the enum is
declared in the same module. It fires for a generic enum (`impl O[T]`) too. A struct has
no variants, so its associated functions never warn, nor does a function whose name no
variant has. A method that takes `self` is W0016 instead, since a value still reaches it.

Rename the function. `--allow W0015` silences the warning. This is a warning, so it does
not fail the build; `--deny-warnings` promotes it (and every warning) to an error.
