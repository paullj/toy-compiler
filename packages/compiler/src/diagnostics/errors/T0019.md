# T0019: a mutable place is required

A method declared with a `mut self` receiver mutates the receiver in place: the
call passes the receiver *by address*, so the receiver must be a mutable,
addressable variable — a local, or a field of one — not a temporary value.

```
struct P { x: int, y: int }
impl P { fn bump(mut self, d: int) { self.x = self.x + d } }

fn main() -> int {
    P{ x: 40, y: 0 }.bump(2)   // error: receiver is a temporary, not a place
    return 0
}
```

Bind the receiver to a local first, then call the method on it:

```
fn main() -> int {
    p := P{ x: 40, y: 0 }
    p.bump(2)                  // ok: `p` is a mutable local
    return p.x
}
```

A field of a local is also a valid receiver (`q.inner.bump(2)` when `q` is a
local), and so is a `Vec` element or a field of one (`ps[i].bump(2)`): the element is
copied in, the method changes the copy, and the copy is written back after the call.
A plain `self` (by-value) method has no such restriction — it copies the
receiver and can be called on any value, including a temporary.

## `mut` parameters

A `mut` parameter works the same way: the call passes the argument *by address*,
and the callee's writes reach the caller's variable. So the argument must be a
mutable place too — a local (a parameter, a loop variable or a match binding
included), a `Vec` element, or a field or tuple field of either. An element is copied
in where the argument is evaluated and written back after the call.

```
fn bump(mut n: int) { n = n + 1 }
fn reset(mut f: fn(int) -> int) { f = fn(v: int) -> int { v } }
fn one() -> int { 1 }

fn main() -> int {
    bump(1)        // error: argument 1 must be a mutable place (a local, a Vec element, or a field of either); 'bump' takes it as 'mut'
    bump(one())    // error: a call result is a temporary
    fn twice(v: int) -> int { v * 2 }
    reset(twice)   // error: a local function's name is never reassigned
    acc := Acc{ n: 1 }
    reset(acc.plus) // error: argument 1 is a method value, not a place; a bound method is a fresh closure
    return 0
}
```

These are fine:

```
fn twice(mut n: int) {
    bump(n)        // ok: forwards the caller's place
    bump(n)
}

fn main() -> int {
    c := 0
    bump(c)        // ok: c is 1
    p := P{ x: 0 }
    bump(p.x)      // ok: p.x is 1
    twice(c)       // ok: c is 3
    xs: Vec[int] = [1, 2]
    bump(xs[0])    // ok: the element is copied in, bumped and written back; xs[0] is 2
    return c + p.x + xs[0]
}
```

To pass a value that is not a place, copy it into a local first and read the local
after the call: `t := one()`, then `bump(t)`.

## A bound `mut self` method on an element

A bound method value keeps its receiver past the binding, but a `Vec` element is
copied in and written back only around a call, so binding a `mut self` method on one
is an error:

```
f := ps[0].bump    // error: cannot bind mutating method 'bump' to a Vec element; the receiver must be a local variable
ps[0].bump()       // ok: a call writes the element back
```

## A capture's `_` at a `mut` parameter

`bump(_)` means `fn(v) { bump(v) }`. Its `v` is a copy of the value the capture is
called with, so a `mut` parameter would change only that copy, and the change would be
lost:

```
f := bump(_)     // error: argument 1 is a capture's '_', a copy of the value it is called with
```

Write the call where the variable is: `bump(c)`. A pipe `c |> bump(_)` is `bump(c)`,
so it is fine for a local `c`.
