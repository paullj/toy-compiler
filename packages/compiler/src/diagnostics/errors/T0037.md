# T0037: extern invalid type

An `extern fn` may only use the C-ABI types the backend can marshal across the
AAPCS64 boundary: `int` (any width), `rawptr` (a C `void*`), `bool`, and `float` (an
f64 riding the V-register sequence, matching C `double`). A parameter or return type
outside that set (a struct, an enum, a `Vec`) is rejected.

```
extern fn frobnicate(p: Point) -> int   // error: a struct is not a valid extern type
extern fn puts(s: str) -> int32         // error: a str is not a C string
```

A `str` is a pointer and a length with no NUL at the end, so a C function that reads
a `const char*` would run past it. Only the bundled `core/` modules may use a `str`
in an extern signature, where it spreads to a C `(const char* buf, size_t len)` pair
for functions such as `write`.

Fixes:

- Pass a `rawptr` (a C `void*`) or a scalar.
- Restrict parameters and the return type to `int`, `float`, `rawptr`, or `bool`.
