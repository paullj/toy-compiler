# T0029: field blocks structural `Eq` derive

`==`/`!=` on a struct or enum with NO explicit `Eq` impl try to derive one
structurally: a struct conforms to `Eq` when EVERY field's type conforms to `Eq`
(recursively), and an enum conforms when every variant is empty (payload-less). The
builtin scalars (`int`/`bool`/`str`/`unit`) always conform, so an all-scalar struct
derives `Eq` for free — no impl needed.

The derive fires only when it can. If a field's type does NOT conform to `Eq`, the
struct cannot derive it, and the operator reports the FIRST offending field by name:

```
enum Color { R(int), G, B }   // has a payload variant => does NOT conform to Eq
struct Bad { c: Color }

fn main() -> int {
    a := Bad{ c: Color.G }
    b := Bad{ c: Color.G }
    return if a == b { 1 } else { 0 }
    // error: cannot derive 'Eq' for 'Bad': field 'c' of type 'Color' does not conform to 'Eq'
}
```

Two fixes:

- Make the offending field's type conform. Give it its own `Eq` impl, or (for a
  struct/empty enum) let it derive structurally by making ITS fields conform. A
  payload-carrying enum has no structural `Eq` derive yet, so it
  needs an explicit `impl Color has Eq { .. }`.
- Or give the OUTER type an explicit `impl Bad has Eq { .. }`, which overrides the
  derive entirely and decides equality however you like (an explicit impl always wins
  over the structural derive).

The derive is lazy: an unused type synthesizes no code. It only runs at a `==`/`!=`
use site, which is where this error surfaces.
