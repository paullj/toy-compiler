# T0034: integer literal out of range for its type

An integer literal adopts the width of the type it is assigned or annotated with, and
its value must fit that width. A literal too large for the target width is rejected —
the value would not round-trip.

Each width has a fixed range:

| type              | range                          |
|-------------------|--------------------------------|
| `int8` / `uint8`  | `-128..127` / `0..255`         |
| `int16` / `uint16`| `-32768..32767` / `0..65535`   |
| `int32` / `uint32`| `±2^31` / `0..2^32-1`          |
| `int64` / `uint64`| `±2^63` / `0..2^64-1`          |
| `int` / `uint`    | platform word (`±2^63` / `0..2^64-1`) |

```
fn main() -> int {
    a: int8 = 200        // error: 200 > 127
    return 0
    // error: literal out of range for type 'int8'
}
```

Fixes:

- Pick a wider type: `a: int16 = 200` (or `uint8 = 200`, since `200 <= 255`).
- Use a value within the type's range.

An UNANNOTATED literal defaults to platform `int` and is range-checked too: a value past
`2^64-1` cannot fit any 64-bit word, so `x := 18446744073709551616` is rejected here
rather than escaping to codegen.

The literal's base does not matter — `0xC8`, `0o310`, `0b11001000`, and `200` are the
same value and all overflow `int8` identically. Underscores (`1_000`) are digit-group
separators and are ignored when computing the value.
