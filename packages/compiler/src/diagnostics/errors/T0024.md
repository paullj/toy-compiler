# T0024: conformance signature mismatch

An `impl <T> has <P>` block provides a method whose SIGNATURE does not match the one
the protocol declares. Providing a method by name (T0021) is not enough — the
parameter types and the return type must match the protocol's declaration too, with
`Self` read as the conforming type. This matters because a bounded generic body
(`[T has P]`) type-checks calls on `T` against the PROTOCOL's declared signature; an
impl whose signature diverges would miscompile at the instantiation.

```
protocol Doubler { fn dbl(self) -> int }
struct P { x: int }

impl P has Doubler {
    fn dbl(self) -> bool {      // error: impl method 'dbl' has a signature incompatible with protocol 'Doubler'
        self.x > 0
    }
}
```

Make the impl method's parameters and return type match the protocol declaration
(here, `fn dbl(self) -> int`).
