# W0010: dead store

A value was written to a local and then overwritten by a later assignment before
anything read it. The first write is a dead store: the computation on its right-hand
side is thrown away without ever being observed, which is wasted work and usually a
logic slip — a leftover line, or an assignment meant for a different variable.

To stay trustworthy this warning is deliberately narrow. It fires only when two writes
to the *same* local appear in one block's straight-line statement list with no read of
that local between them. Anything that could read the first value keeps it live and is
never flagged: a read in the overwriting assignment itself (`x = x + 1`), an intervening
statement that reads it (`y := x`), or *any* control flow between the two writes — an
`if`, `while`, `for`, `loop`, `match`, labeled block, nested block, `return`, `break`,
or `continue`. Only a bare local name is considered; a store through a field, tuple
element, or dereference (`p.x = …`, `*r = …`) is never flagged.

For example, `x := 1` followed by `x = 2` with no read of `x` in between flags the
`x := 1`. Delete the dead assignment, or restructure so the first value is used.

Prefix the local with an underscore (`_x`) to silence a store you intend to discard.
This is a warning, so it does not fail the build; `--deny-warnings` promotes it (and
every warning) to an error, and `--allow W0010` silences it.
