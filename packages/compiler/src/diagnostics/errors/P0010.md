# P0010: angle-bracket type arguments

Type arguments are written with square brackets, not the angle brackets `<>` used
by C++, Rust, or TypeScript. This error means a type or a generic call was followed
by `<...>`.

    xs: Vec[int]                        // right
    fn first(xs: Vec[int]) -> int { }
    v := Vec[int].new()
    n := id[int](3)

Rewrite the angle brackets as square brackets: `Vec<int>` becomes `Vec[int]`,
`Map<str, int>.new()` becomes `Map[str, int].new()`, and `f<int>(x)` becomes
`f[int](x)`.

In a type position (an annotation, a return type, a parameter, a field, or a nested
type argument) `<` can only be a type argument list. In an expression, `<` and `>`
are the comparison operators, so `f<int>(x)` first reads as two comparisons. It is
reported as P0010 only when that reading fails in a way the type arguments explain:
it compares a type name, the comma in `Map<str, int>` breaks the parse, or the `new`
in `Vec<int>.new()` reads as an undeclared name. Any other error, such as a typo in
`g(a < b, cz > (d))`, is reported as itself. A program that compiles is never
reinterpreted.
