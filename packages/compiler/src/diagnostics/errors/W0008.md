# W0008: unused Result or Option

An expression statement produces a `Result` or `Option` value that is then discarded.
The whole point of these types is that the caller decides what to do with the error or
the absence — a `Result` that is dropped throws its error away, and a dropped `Option`
throws away the "nothing" case. A silently dropped `Result`/`Option` is almost always a
bug: the failure it was reporting goes unhandled.

This warns only on `Result` and `Option`. Dropping a plain value — an `int`, a `str`,
`()`, or any other type — is not flagged; those carry no obligation to be handled. A
value is only "dropped" when it sits in statement position and is thrown away: a trailing
expression that is the block's or function's value is used (returned), not dropped, so it
never warns.

Handle it (`match e { .. }` or an `if`), bind it (`x := e`), discard it on purpose
(`_ := e`), or propagate it (`e?`). If the drop is intentional, `_ := e` makes that
explicit and silences the warning; `--allow W0008` silences it wholesale. This is a
warning, so it does not fail the build; `--deny-warnings` promotes it (and every warning)
to an error.
