# T0025: ambiguous conformance

A type may conform to a generic protocol (`protocol P[X]`) more than once, once per set of
protocol type-args, and it may conform to two protocols that require a method of the same
name. A call of that method with nothing to choose between the conformances is ambiguous:
the compiler will not silently pick one witness. This holds on a generic type
(`impl Box[T] has Into[int]`) as on a concrete one.

```
struct P { x: int }

impl P has Into[int]  { fn into(self) -> int  { self.x } }
impl P has Into[bool] { fn into(self) -> bool { self.x > 0 } }

fn main() -> int {
    p := P{ x: 42 }
    return p.into()             // error: ambiguous conformance — Into[int] vs Into[bool]
}
```

Name the protocol type-args at the call site:

```
    return p.into[int]()        // selects `impl P has Into[int]`
```

The expected type does not choose: `n: int = p.into()` is this error too. A method value
cannot take protocol type-args (`f := p.into[int]` is this error too), so call the method
in a lambda instead:

```
    f := fn() { p.into[int]() }
```

Two protocols without type-args (`Show` and `Debug`, both requiring `render`) cannot be
named at a call. Call the method through a generic fn bounded by one of them; the bound
says which `render` it means:

```
fn render_via[T has Show](x: T) -> int { x.render() }

    return render_via(p)        // selects `impl P has Show`
```

A generic type cannot meet a bound yet, so on one no call can choose between such
conformances. A type that conforms only ONCE resolves with no explicit args and never trips
this.
