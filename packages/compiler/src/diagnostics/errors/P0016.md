# P0016: misplaced capture

A `_` that is a whole call argument makes the call a function of one parameter:
`add(1, _)` means `fn(v) { add(1, v) }`. A call takes one `_`, because the function it
makes takes one parameter.

    inc := add(1, _)       // right: fn(v) { add(1, v) }
    f := add(_, _)         // error: a second '_' in one call
    g := add(_, 1, _)      // error: a second '_' in one call
    h := 3 |> add(_, _)    // error: the pipe fills one '_', not two

For a function of more than one parameter, write the lambda out:

    f := fn(a: int, b: int) { add(a, b) }

Each call has its own `_`, so `f(g(_), _)` is two captures, one for `g` and one for
`f`, and is not this error.

A method pipe passes the piped value as the receiver, so its arguments take no `_`:

    x |> .m(1, _)          // error: x is already the receiver of m
    x |> .m(1)             // right: x.m(1)
