# W0005: unreachable code

A statement can never run because a statement before it in the same block always
diverges — control leaves the block (or the whole function) at the earlier statement
and never reaches this one. The dead statement is a leftover: it contributes nothing,
and usually means an edit left a line stranded past the point where control departs.

A preceding statement always diverges when it is a `return`, a `break`, or a `continue`
(control leaves the block), a `panic(..)` (execution aborts), an `if`/`else` whose two
arms both diverge (every path leaves), or an exhaustive `match` whose arms all diverge.
After any of these, the next statement in the same block is unreachable.

A construct that control can fall through does NOT make what follows unreachable: an
else-less `if` may skip its body, and a `while` or a bare `for` may run zero times or
exit normally, so a statement after one of them is reachable and is not flagged. Only
the FIRST unreachable statement in a block is reported; the rest of the dead tail is
implied by it, not enumerated. A block sitting in a reachable position is analysed on
its own, so unreachable code nested inside it is still found.

Fix it by removing the unreachable statement. Removing code that can never run cannot
change behavior. There is no `_`-prefix silence for a statement; if you want to keep it
anyway, `--allow W0005` silences the warning. This is a warning, so it does not fail the
build; `--deny-warnings` promotes it (and every warning) to an error.
