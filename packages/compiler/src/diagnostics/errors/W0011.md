# W0011: method shadows a std method

A method the program declares has the name of a method that a bundled std module
declares on the same type: an `impl Vec[T] { fn each .. }` next to `std/vec`'s own
`each`, or an `impl str { fn trim .. }` in a program that `std/str` is part of.

```
import std/vec

impl Vec[T] {
    fn each(self, f: fn(T)) { .. }   # W0011: method 'each' on 'Vec' shadows the one in std/vec
}
```

This is not an error, and the program's method wins: every call of that name on that
type reaches it, whatever the import order, and that includes the calls inside std's
own bodies. std's method is then never used, and a std method that called it now runs
the program's code instead, which can change what std does.

The warning fires only when the std module is part of the program, imported directly
or through another module (`std/set` brings in `std/map`, which brings in `std/vec`),
because only then is there a std method to shadow. It sits on the program's method
declaration and names the type, the method and the std module.

Rename the method (`each_back`, say) to keep both: calls of `each` then reach std's,
and the program calls its own by the new name. If the shadowing is intended, `--allow
W0011` silences it. This is a warning, so it does not fail the build; `--deny-warnings`
promotes it (and every warning) to an error.
