# T0018: no such method

A method call `x.m(..)` named a method `m` that the receiver's concrete type does
not have. Inherent methods live in an `impl` block for that exact type; only the
methods declared there (with `self` as their first parameter) are callable on a
value of the type.

```
struct P { x: int, y: int }
impl P { fn sum(self) -> int { self.x + self.y } }

fn main() -> int {
    p := P{ x: 20, y: 22 }
    return p.nope()   // error: P has no method 'nope'
}
```

Check for a typo in the method name, or add the method to an `impl` block for the
receiver type. Note that a bare field access (`x.field`) is a field read, not a
method call — only `x.m(..)` (with the call parentheses) is dispatched as a method.

An associated function (an `impl` fn without `self`) is called on its type, as
`K.make(..)` on a struct or enum `K` or `Box[int].new()` on a generic one, never on a
value: `k.make(1)` is this error, "'make' is an associated function; call it as
'K.make(..)'". When the struct also has a field of function type with that name, the call
still does not reach the field, and the message names both ways in: "'run' is both an
associated function of 'H' and a field of fn type: 'H.run(..)' calls the function and
'h.run' reads the field". To call the field, read it first (`f := h.run`, then `f(1)`).
The other way round, an instance method named on its type (`K.get()`) is "'get' is an
instance method, not an associated function; call it on a value", and a name the type's
`impl` does not declare is "'K' has no associated function 'nope'".

Explicit type arguments on a method that has no type parameters of its own are protocol
arguments: they pick one of the receiver's conformances to a generic protocol
(`b.into[int]()`, on a concrete or a generic receiver). When no conformance of the
method's protocol has them, or the method is inherent, the call is this error, worded
"no method 'into' on type 'Box' for the given protocol type arguments". Drop the `[..]`,
or name the protocol arguments of a conformance the type has.

Some methods of prelude types come from a std module: `Ref`'s from `std/ref`; `map`,
`then`, `or_else` and `map_error` on `Option` / `Result` from `std/option`; and `split`,
`join`, `trim`, `contains`, `starts_with`, `ends_with`, `replace` and `chars` on `str`
from `std/str`. Without the import, the error names it: "no method 'map' on type
'Option'; add 'import std/option'".
