# T0018: no such method

A method call `x.m(..)` named a method `m` that the receiver's concrete type does
not have. Inherent methods live in an `impl` block for that exact type; only the
methods declared there (with `self` as their first parameter) are callable on a
value of the type.

```
struct P { x: int, y: int }
impl P { fn sum(self) -> int { self.x + self.y } }

fn main() -> int {
    p := P{ x: 20, y: 22 }
    return p.nope()   // error: P has no method 'nope'
}
```

Check for a typo in the method name, or add the method to an `impl` block for the
receiver type. Note that a bare field access (`x.field`) is a field read, not a
method call — only `x.m(..)` (with the call parentheses) is dispatched as a method.

A method of a generic type cannot take explicit type arguments yet: on a `b: Box[int]`,
`b.scale[int](3)` (or `b |> .scale[int](3)`) is this error, worded "'scale' on the
generic type 'Box' takes no explicit type arguments yet". The method exists; drop the
`[..]` and call `b.scale(3)`.

Some methods of prelude types come from a std module: `Ref`'s from `std/ref`, and `map`,
`then`, `or_else` and `map_err` on `Option` / `Result` from `std/option`. Without the
import, the error names it: "no method 'map' on type 'Option'; add 'import std/option'".
