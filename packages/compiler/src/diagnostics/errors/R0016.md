# R0016: library not found

An `extern "name"` block or a `-l name` flag names a library that the linker cannot
find. A plain name is looked up as `lib<name>.dylib` in each `-L` folder, in order,
then in `/usr/local/lib` and `/usr/lib`, then in the dyld shared cache (where macOS
keeps its system libraries, such as `libz` and `libsqlite3`, with no file on disk).
A name that contains a `/` or ends in `.dylib` is a path, used as given (relative to
the working directory), and must exist.

```
// toy build main.toy
extern "toyffi" {         // error: library 'toyffi' not found: no libtoyffi.dylib in
    fn toyffi_add(a: int, b: int) -> int   // /usr/local/lib, /usr/lib, the dyld shared cache
}
```

The error lists every folder it searched. A `-l` flag that finds nothing is a usage
error (exit 2) naming the flag; a library named in source is reported at its block.

Fixes:

- Pass the folder that holds the library: `toy build main.toy -L path/to/lib`.
- Check the spelling: `extern "sqlite3"` looks for `libsqlite3.dylib`, without the
  `lib` prefix or the extension.
- Or name the file by path: `extern "./vendor/libfoo.dylib"`.
