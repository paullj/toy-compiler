# R0018: extern library conflict

A C symbol is a single name in the binary's import table, so it comes from one
library. Two externs declare the same C function but bind it to different libraries
(two `extern "name"` blocks, or one block and a bare `extern fn`, which binds to
libSystem). The error is at the second declaration and names the first.

```
extern "z" { fn crc32(crc: int, p: rawptr, n: int) -> int }
extern fn crc32(crc: int, p: rawptr, n: int) -> int   // error: C symbol 'crc32' is bound to
                                                      // library 'libSystem' here but to 'z'
```

The rule covers every module of the program, the bundled standard library included,
and the symbols the toy runtime imports itself (`malloc`, `free`, `write`, ...): a
block that binds `write` or `strlen` to another library conflicts with the one std
uses. Such a conflict is reported at the block's extern, since the standard library
cannot be edited.

Fixes:

- Declare the function once, in the block of the library that exports it, and import
  that module where it is needed.
- If two libraries really export the same name, only one of them can be used.
