# T0015: conflicting types for an inferred type parameter

A bare (no-explicit-args) generic call infers each type parameter by matching the
argument types against the template's parameter patterns. When one type parameter
is matched against two *different* concrete types, inference cannot pick one — the
call is ambiguous and rejected.

```
fn same[T](a: T, b: T) -> T { a }
fn main() -> int { return same(1, true) }   // T = int here, T = bool there
```

Both argument spans are named (the earlier binding and the later conflicting one).
Give the arguments the same type, or supply explicit type arguments to override
inference — `same[int](1, 1)`.
