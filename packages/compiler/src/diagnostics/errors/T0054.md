# T0054: wrong type arguments

A call, a protocol reference or an intrinsic is given type arguments it does not
take, or the wrong number of them.

```
fn add(a: int, b: int) -> int { a + b }
fn pair[A, B](a: A, b: B) -> A { a }

fn main() -> int {
    x := add[int](1, 2)        // error: 'add' is not generic; drop the type arguments
    y := pair[int](1, true)    // error: expected 2 type argument(s), got 1
    g := fn(v: int) { v }
    z := g[int](3)             // error: 'g' is not generic; drop the type arguments
    return x + y + z
}
```

A method of a generic type takes exactly as many as it declares of its own (the impl's
come from the receiver): with `fn none[U](self) -> Option[U]`, `b.none[int, bool]()` is
"'none' takes 1 type argument(s) of its own, got 2". An associated fn or a variant of a
non-generic type takes none (`K.make[int]()`).

A function value (a lambda, a local fn, a parameter of function type) is never
generic, so it takes no type arguments. A protocol reference `P[A, B]` must give
exactly as many as the protocol declares, and the core intrinsics `size_of`,
`align_of`, `descriptor_of` and `gc_array` take exactly one.

Fixes:

- Drop the `[..]` on a function that is not generic.
- Give exactly as many type arguments as the function or protocol declares, or
  leave them all out and let the call infer them.
