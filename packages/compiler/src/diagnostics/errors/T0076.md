# T0076: receiver mode differs from the protocol's

A method in an `impl T has P` block takes its receiver as `mut self` where the protocol
declares `self`, or as `self` where it declares `mut self`. The two pass the receiver
differently: `self` gets a copy, `mut self` gets the caller's variable by address. An
operator or loop that calls the method for you (`==` and `!=` for `Eq`, `<` for `Ord`,
`+` for `Add`, `io.println` and `to_string` for `Display`, a `Map` or `Set` key's
`Hash`, `for`'s `next` for `Iterator`) knows only the protocol, and so does generic
code that calls `t.m()` on a `T has P`: it passes a copy for `self` and the caller's
address for `mut self`, whichever type fills in `T`. So the method must take its
receiver the way the protocol says, in both directions.

Why not let a `self` method satisfy a `mut self` requirement, as Swift does? Every call
through the protocol passes an address, so each such witness would need an adapter that
loads the value and calls it, or each call site would have to check the witness's real
mode, and boxing and "mutated by" hints would differ between concrete and generic calls.
One calling convention per protocol method keeps a simple rule and a simple error
([#48](https://github.com/paullj/toy-compiler/issues/48)). The other direction can never
work: a `mut self` witness given a copy would write the copy, and the change would be lost.

```
struct P { x: int }

impl P has Eq {
    fn eq(mut self, o: P) -> bool { self.x == o.x }   // error: impl method 'eq' takes 'mut self', but protocol 'Eq' declares 'self'; write 'self'
}

struct Count { n: int }

impl Count has iter.Iterator[int] {
    fn next(self) -> Option[int] { Option.some(self.n) }   // error: impl method 'next' takes 'self', but protocol 'Iterator' declares 'mut self'; write 'mut self'
}
```

The prelude protocols (`Eq`, `Ord`, `Add`, `Sub`, `Mul`, `Div`, `Hash`, `Display`,
`From`, `Into`) declare `self`; `std/iter`'s `Iterator.next` declares `mut self`, since
an iterator advances its own state. A read-only `next` that changes nothing still
writes `mut self`; its callers then pass a place, as any `mut self` call does (T0019).
To change state from a `self` method, keep it in a `Ref` field.
