# W0004: unused import

An `import a/b` binds the module but nothing in the importing module ever uses it. It
is dead: it names a dependency that contributes nothing, and usually means a leftover
from an edit or an intended reference that was never wired up.

An import counts as used several ways, and any one is enough. It is used *qualified*
when the module names a member through its namespace (`b.member` — `io.print`,
`math.sqrt`, `geom.Rect`, `mod.Enum.Variant`). It is used via a *bare type* when the
module names a `pub` struct or enum the import brings into scope unqualified (`Vec`
from `import std/vec`), including a `[..]` list literal that constructs a `Vec` and a
`for k, v in m` that needs the `Entry` its iterator yields — both name their library
type without ever spelling it. It is also used when the module it names declares any
`impl` — an inherent-method block or a protocol conformance — because the importer can
reach those methods through method-call or operator dispatch that binds only during type
checking, which this check cannot observe; every impl-bearing import is credited so such
a program is never wrongly flagged. Used any of these ways, the import is kept.

Fix it by removing the import. Removing a genuinely-unused import never changes behavior.
If you want to keep an import you know is currently unused — deliberately dead, staged for
a future edit — alias it with a leading underscore (`import a/b as _b`): there is no
`_`-prefix for a bare module path, so the alias carries the intent. A namespace whose
bound name begins with `_` is treated as deliberately unused, exactly like a `_`-prefixed
variable, parameter, or function.

`core/` and `std/` internal imports are evaluated the same way. This is a warning, so
it does not fail the build; `--deny-warnings` promotes it (and every warning) to an
error, and `--allow W0004` silences it.
