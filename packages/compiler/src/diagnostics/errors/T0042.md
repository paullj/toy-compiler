# T0042: return type mismatch

A `return` statement, or the value a body ends with, has a type that differs from
the function's declared return type.

```
fn name() -> int {
    return "toy"   // error: return type str does not match declared int
}

fn flag() -> bool {
    1              // error: value int does not match declared return type bool
}
```

A body that ends with no value at all is T0043 (missing return) instead.

A lambda with no `-> R` takes its return type from the function type expected for
it: a parameter's type, a binding's annotation. It declared nothing, so the message
spells the type the lambda really has next to the one it is expected to have:

```
xs.filter(fn(x) { x % 2 })
// error: lambda has type fn(int) -> int, but fn(int) -> bool is expected: its value is int, not bool

xs.filter(fn(x) { return x })
// error: return type int does not match expected bool (the lambda is expected to be fn(int) -> bool)
```

A lambda whose annotated parameter differs from the expected one does not fit that
type at all, so it keeps the return type of its own body, and the call reports the
whole mismatch (T0040, `got fn(bool) -> int`).

A lambda with no `-> R` and no expected type joins its `return`s and its final
value; two that differ are this error too ("does not match the lambda's earlier
return type").

Fixes:

- Return a value of the declared (or expected) type, e.g. `x % 2 == 0` for a `bool`.
- Change the declared return type (after `->`) to the type you actually return.
