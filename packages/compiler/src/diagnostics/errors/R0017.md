# R0017: not a dylib

The library file was found but cannot be linked: it is not a Mach-O file, it is not
built for arm64, it is an executable or a bundle rather than a dynamic library, or it
has no install name (`LC_ID_DYLIB`). toy reads the install name and versions from the
library, so the binary it writes records where dyld will find it at run time.

```
// vendor/libfoo.dylib is really a text file, or an x86_64-only build
extern "./vendor/libfoo.dylib" { fn foo() }   // error: library './vendor/libfoo.dylib'
                                             // cannot be linked: ...: it is not built for arm64
```

A universal (fat) library works when it holds an arm64 slice.

Fixes:

- Rebuild the library for arm64 macOS as a dynamic library (`cc -shared -arch arm64`).
- Check that the path names the library and not another file.
