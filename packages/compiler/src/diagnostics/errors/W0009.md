# W0009: shadowed binding

A new binding — a `:=` local, a `for`-loop variable, or a function parameter — was
declared with a name that already refers to something in scope. The new name silently
hides the old one for the rest of the block: any use of that name now reaches the inner
binding, and the outer one becomes unreachable until the inner scope ends. That is
usually accidental — a reused name that was meant to be distinct — and it makes the code
harder to read, since the same name means two different things.

Two things can be shadowed. An enclosing lexical binding — an outer local or a parameter
of the same function — is reported with a secondary label at the outer definition. A
seeded builtin (such as `panic`) is reported as shadowing a builtin. Shadowing your own
module's functions with a local is common and low-risk, so it is not flagged; only an
enclosing lexical binding or a builtin counts. A second binding of the same name in the
*same* scope is a redeclaration error, not this warning.

Rename the inner binding to a distinct name, or prefix it with an underscore (rename `x`
to `_x`) if the hide is deliberate. Reusing a name across two sibling blocks that do not
nest is fine and never warns. This is a warning, so it does not fail the build;
`--deny-warnings` promotes it (and every warning) to an error, and `--allow W0009`
silences it.
