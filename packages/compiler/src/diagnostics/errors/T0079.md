# T0079: extern call outside unsafe

A call to an `extern fn` must sit inside an `unsafe { }` block. The compiler cannot
check what a C function does with its arguments: a wrong length or a dangling
`rawptr` corrupts memory with no error, so each call is fenced explicitly.

```
extern fn labs(x: int) -> int

fn main() -> int {
    return labs(-3)            // error: needs an unsafe block
}
```

```
fn main() -> int {
    return unsafe { labs(-3) } // ok
}
```

An extern is a symbol of another library, not toy code, so it cannot be taken as a
value either (**T0049**).

Fixes:

- Wrap the call in `unsafe { ... }`.
- Write a safe toy function around the call that checks its inputs, and call that
  instead; the standard library wraps its own externs this way.
