# T0052: a closure cannot capture this variable yet

A lambda may name the locals and parameters of the function it is written in: it
captures them. A local that is only read is copied into the closure; one that is
also assigned anywhere (`x = ..`, a field store `x.f = ..`, or a call of a
`mut self` method on `x`) lives in a shared box, so the closure and the function
see each other's writes. A bound method (`f := acc.plus`) captures its receiver the
same way.

Two kinds of capture are not supported yet.

A capture of a **`mut self` receiver**. Inside a `mut self` method, `self` refers to
the caller's variable, not to a value of the method's own that a closure could copy
or box. That holds for reading `self`, for storing to its fields, for calling
methods on it and for binding one of its methods.

```
impl Counter {
    fn report(mut self) -> int {
        f := fn() -> int { self.n }   // error: a closure cannot capture the 'mut self' receiver 'self'
        g := self.get                 // error: the same, through a bound method
        f() + g()
    }
}
```

A **`mut self` method bound on a field**. The bound value writes its receiver on
every call, so the receiver must live in a box, and only a local variable can be
moved into one: a field is part of the value around it.

```
fn main() -> int {
    h := Holder { c: Counter { n: 0 } }
    inc := h.c.bump   // error: binding the 'mut self' method 'bump' needs a local receiver, not a field
    inc()
    return h.c.n
}
```

Fixes:

- Copy what the lambda reads into a local first: `n := self.n`, then
  `f := fn() -> int { n }`.
- To let the lambda change the receiver, make the method take `self`, return
  the updated value and assign it at the call site.
- For a field, bind the method on a local and store it back:
  `c := h.c`, `inc := c.bump`, then after the calls `h.c = c`.
