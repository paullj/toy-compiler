# T0052: a closure cannot capture this variable

A lambda may name the locals and parameters of the function it is written in: it
captures them. A local that is only read is copied into the closure; one that is
also assigned anywhere (`x = ..`, a field store `x.f = ..`, or a call of a
`mut self` method on `x`) lives in a shared box, so the closure and the function
see each other's writes. A bound method (`f := acc.plus`) captures its receiver the
same way.

Two kinds of capture are errors.

A **`mut` parameter**, a `mut self` receiver included, captured by a closure that
**escapes**. Inside the function, the parameter refers to the caller's variable, so
a closure that captures it holds the caller's address. That is fine while the call
runs, but a closure that escapes (one that is returned, stored in a field, a struct
or a `Vec`, compared, captured by another closure that escapes, assigned to a local,
or passed to a function that keeps it, to a function value or to a builtin) could be
called after the caller's variable is gone. This holds for a lambda, a local
function, a `_` capture and a bound method on the parameter alike, and it is the same
at every opt level.

```
fn peek(mut n: int) -> fn() -> int {
    fn() -> int { n }   // error: a closure that escapes cannot capture the 'mut' parameter 'n'
}

impl Counter {
    fn reader(mut self) -> fn() -> int {
        self.get        // error: a closure that escapes cannot capture the 'mut self' receiver 'self'
    }
}
```

A closure that does not escape may capture it: one that is only called, or only
passed to parameters that only call it.

```
fn add_all(mut n: int, xs: Vec[int]) {
    each(xs, fn(v: int) { n = n + v })   // fine: `each` only calls `f`
}

fn twice(mut p: Point) -> int {
    g := p.get                          // fine: `g` is only called
    g() + g()
}
```

Whether a closure escapes can depend on another function's body: if `each` starts
storing `f`, the capture in `add_all` becomes this error.

A generic function is checked even when nothing calls it, so a library reports its own
escaping captures: a closure it returns or stores escapes in every instance. A call
whose callee depends on the type arguments (a generic function, a protocol method of
`T`) is judged per instance instead, once something instantiates the function.

A **`mut self` method bound on a field**. The bound value writes its receiver on
every call, so the receiver must live in a box, and only a local variable can be
moved into one: a field is part of the value around it.

```
fn main() -> int {
    h := Holder { c: Counter { n: 0 } }
    inc := h.c.bump   // error: binding the 'mut self' method 'bump' needs a local receiver, not a field
    inc()
    return h.c.n
}
```

Fixes:

- Copy what the closure reads into a local first: `m := n`, then
  `fn() -> int { m }`; for a receiver, `v := self.n`.
- Or keep the closure from escaping: call it, or pass it only to functions that
  call it, instead of returning or storing it.
- To let the closure change the receiver, make the method take `self`, return
  the updated value and assign it at the call site.
- For a field, bind the method on a local and store it back:
  `c := h.c`, `inc := c.bump`, then after the calls `h.c = c`.
