# W0014: two mut arguments are copies of one element

A `Vec` element has no address, so a `mut` argument rooted at one (`xs[i]`, or a field
chain like `ps[i].x`) and a `mut self` receiver rooted at one (`ps[i].bump()`) are
copy-in/copy-out: the element is copied in where the argument is, the callee writes the
copy, and after the call each copy is written back whole, in argument order, the
receiver first. Two such places of one call that name one element are two copies of it,
and only the last write-back is kept, even when they name different fields:

```
import std/vec

struct P { x: int, y: int }

fn swap(mut a: int, mut b: int) {
    t := a
    a = b
    b = t
}

fn main() -> int {
    ps := [P { x: 1, y: 2 }]
    swap(ps[0].x, ps[0].y)   # W0014: arguments 1 and 2 are copies of one element 'ps[0]'
    return ps[0].x * 10 + ps[0].y   # 11, not 21: the change to x is lost
}
```

With a local, `swap(p.x, p.y)` passes two addresses into `p` and swaps them, so the same
code gives a different result on an element. The warning sits on the later argument and
points at the earlier copy.

It fires when both places name the same `Vec` and the same index, each read the same
way: the same integer literal, the same local, or the same field, tuple-field or
element chain of them (`b.ps[s.i]` twice). `swap(xs[0], xs[0])` warns too. Indexes that
may differ do not warn (`ps[i].x` with `ps[j].y`), nor do other elements (`ps[0]` with
`ps[1]`), other `Vec`s, or places rooted at a local. Nor does a pair with an argument
between them that may write, such as a call: in `f(ps[i].x, bump(i), ps[i].y)`, `bump`
can change `i`, so the two places may be two elements.

To keep both writes, copy the element into a local, pass its fields, then store it back:

```
    p := ps[0]
    swap(p.x, p.y)
    ps[0] = p
```

If the overwrite is intended, `--allow W0014` silences it. This is a warning, so it does
not fail the build; `--deny-warnings` promotes it (and every warning) to an error.
