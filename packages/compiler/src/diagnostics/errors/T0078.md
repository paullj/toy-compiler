# T0078: private field

A struct field is private to the module that declares the struct unless it is
marked `pub`. Outside that module a private field cannot be read, written (also
through `+=` and other compound assignments, or as the base of an element store) or
named in a struct literal. A struct literal that leaves a private field out is T0078
too: only the defining module can build that struct, so use its constructor.

```
// shapes.toy
pub struct Circle { pub r: int, area_cache: int }
pub fn circle(r: int) -> Circle { Circle { r: r, area_cache: 3 * r * r } }

// main.toy
import shapes

fn main() -> int {
    c := shapes.circle(2)
    c.r = 3                                 // ok: r is pub
    return c.area_cache                     // error: field 'area_cache' of 'Circle' is private to module 'shapes'; mark it pub or use a constructor
}
```

Code inside the defining module, including the methods and conformances written
there, sees every field, and so do the derived `Eq`, `Hash`, `Ord` and `Display`,
which belong to that module too. A conformance written in another module does not.
Enum payloads have no visibility of their own.

Outside the module a private field is hidden, so a method of the same name wins:
`a.balance` is the bound method `balance` when the field `balance` is private.

A field of a `std` or `core` struct is reported without "mark it pub", since a
program cannot edit those modules.

Private fields let a module keep an invariant: the standard library's `Vec` and
`Map` hide their storage handle, and their iterators hide their cursor, so no
other code can build one that points at the wrong memory. To let another module
use a field, mark it `pub`; to let it build a value without exposing the fields,
give it a `pub fn` constructor.
