# T0027: missing `Ord` impl

The `<`, `>`, `<=`, and `>=` operators desugar to the prelude protocol `Ord`, which
returns a three-way `Ordering`:

```
enum Ordering { lt, eq, gt }
protocol Ord { fn cmp(self, other: Self) -> Ordering }
```

All four comparisons are composed from the single `cmp`: `a < b` is `cmp(a, b) ==
Ordering.lt`, `a > b` is `== Ordering.gt`, `a <= b` is `!= Ordering.gt`, and `a >= b`
is `!= Ordering.lt`. The builtin scalars — `int` (signed), `str` (lexicographic),
`bool` (`false < true`) — ship compiler `Ord` impls, so comparing them always works. A
user value type (a struct or enum) must provide its own `Ord` impl; using a comparison
operator on one that has none is an error at the operator.

```
struct P { x: int }

fn main() -> int {
    p := P{ x: 1 }
    q := P{ x: 2 }
    return if p < q { 1 } else { 0 }   // error: '<' requires an 'Ord' impl for type 'P'
}
```

Give the type an `Ord` impl:

```
impl P has Ord {
    fn cmp(self, o: P) -> Ordering {
        if self.x < o.x { Ordering.lt } else if self.x == o.x { Ordering.eq } else { Ordering.gt }
    }
}
```

Both operands must have the SAME type — `Ord` is homogeneous (`Rhs = Self`), so a
cross-type comparison is a separate "same type" error even when both sides individually
conform. `Ord` refines `Eq`: an `Ord` impl also satisfies `==`/`!=` (via `cmp ==
Ordering.eq`) unless an explicit `Eq` impl is present, which is authoritative.

Only total orders are supported (there is no float type). A structural auto-derive
(`derive Ord`) is not yet supported; until then the impl is written by hand.
