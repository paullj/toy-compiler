# T0033: `?` operand/return constructor mismatch

The postfix `?` early-returns the operand's residual (`none`/`err`) from the enclosing
function, so the operand's constructor must MATCH the enclosing return type — with no
conversion (M24):

- an `Option` `?` requires the function to return an `Option`, and
- a `Result[_, E]` `?` requires the function to return a `Result[_, E]` with the SAME
  error type `E`.

`?`-ing an `Option` inside a function that returns a `Result` (or vice versa) is a
family mismatch:

```
fn get(o: Option[int]) -> Result[int, str] {
    v := o?          // error: '?' on Option in a function returning Result
    return Result.ok(v)
}
```

`?`-ing a `Result` whose error type differs from the enclosing `Result`'s error type is
an error-type mismatch — the residual `err(e)` could not be re-emitted at the enclosing
type without a conversion:

```
fn get(o: Result[int, bool]) -> Result[int, str] {
    v := o?          // error: '?' error type bool does not match the enclosing Result error type str
    return Result.ok(v)
}
```

Fixes:

- Match the constructors: `Option?` in an `-> Option` function, `Result?` in a
  `-> Result` function.
- Make the two `Result` error types identical, or convert the error explicitly before
  applying `?`.

The happy-payload type (`some`/`ok`) need NOT match — `?` unwraps it locally — only the
residual has to be re-constructible at the enclosing return type. Automatic `From`-style
error widening lands in a later milestone (M25).
