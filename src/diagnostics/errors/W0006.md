# W0006: unreachable match arm

A match arm can never match because earlier arms already cover every value the
scrutinee could take. Control reaches the match, tests the earlier arms, and one of
them always matches first — so this arm's body never runs. The dead arm is a leftover:
it contributes nothing, and usually means an edit left an arm stranded past the point
where coverage was already complete.

The match is already saturated by the preceding UNGUARDED arms when any of these holds:
an unguarded `_` (or a bare binding like `x ->`) has already caught everything; every
variant of the scrutinee enum has already been matched; or both `true` and `false` have
already been matched on a bool scrutinee. An int match saturates only through `_` (its
domain is infinite), so a required int `_` catch-all is the arm that COMPLETES coverage
and is reachable — it is never flagged. The same holds for the first arm that completes
an enum or bool: it is checked before its own contribution, so it is reachable and not
flagged; only an arm strictly after saturation warns.

A guarded arm (`p if cond ->`) may fall through when its guard is false, so it never
saturates the match, and an arm after a guarded-only prefix is reachable and not flagged.
Only the FIRST unreachable arm is reported; the rest of the dead tail is implied by it.

This lint reports coverage saturation ("every value is already matched"), not per-value
overlap: a duplicate literal or variant that does NOT complete coverage (for example a
repeated `true` while `false` is still unmatched) is not flagged.

Fix it by removing the unreachable arm. Removing an arm that can never match cannot
change behavior. There is no `_`-prefix silence for an arm; if you want to keep it
anyway, `--allow W0006` silences the warning. This is a warning, so it does not fail the
build; `--deny-warnings` promotes it (and every warning) to an error.
