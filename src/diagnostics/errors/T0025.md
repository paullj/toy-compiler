# T0025: ambiguous conformance

A generic protocol (`protocol P[X]`) may be implemented more than once for the same
type — once per distinct set of protocol type-args. That is intentional: a type can
convert into several targets. But at a use site where the type conforms MULTIPLE times
and no explicit protocol type-args are given, the call is ambiguous — the compiler will
not silently pick one witness.

```
protocol Into[U] { fn into(self) -> U }
struct P { x: int }

impl P has Into[int]  { fn into(self) -> int  { self.x } }
impl P has Into[bool] { fn into(self) -> bool { self.x > 0 } }

fn main() -> int {
    p := P{ x: 42 }
    return p.into()             // error: ambiguous conformance — Into[int] vs Into[bool]
}
```

Disambiguate by naming the protocol type-args at the call site:

```
    return p.into[int]()        // selects `impl P has Into[int]`
```

A type that conforms to a protocol only ONCE (a non-generic protocol, or a single
generic conformance) resolves with no explicit args and never trips this.
