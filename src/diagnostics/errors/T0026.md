# T0026: missing `Eq` impl

The `==` and `!=` operators desugar to the prelude protocol `Eq`:

```
protocol Eq { fn eq(self, other: Self) -> bool }
```

`a == b` is `a.eq(b)` and `a != b` is `!a.eq(b)`. The builtin scalars — `int`,
`bool`, `str`, `unit` — ship compiler `Eq` impls, so comparing them always works. A
user value type (a struct or enum) must provide its own `Eq` impl; using `==`/`!=` on
one that has none is an error at the operator.

```
struct P { x: int }

fn main() -> int {
    p := P{ x: 1 }
    q := P{ x: 2 }
    return if p == q { 1 } else { 0 }   // error: '==' requires an 'Eq' impl for type 'P'
}
```

Give the type an `Eq` impl:

```
impl P has Eq {
    fn eq(self, o: P) -> bool { self.x == o.x }
}
```

Both operands of `==`/`!=` must have the SAME type — `Eq` is homogeneous (`Rhs = Self`),
so a cross-type comparison is a separate "same type" error even when both sides
individually conform.

A structural auto-derive (`derive Eq`) that synthesizes the field-by-field impl for you
lands in a later milestone (M18); until then the impl is written by hand.
